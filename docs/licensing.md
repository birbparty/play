# Licensing And Third-Party Asset Policy

`play` is intended for commercial and non-commercial games. Keep the repository
usable by projects that need clear, permissive licensing and reproducible
third-party provenance.

## Project Code

Project code is licensed under the Zlib license unless a file or directory
states otherwise. The top-level `LICENSE` file is the source of truth for the
project license and matches the existing `play.nimble` `Zlib` package metadata.
The root license text was aligned with that metadata during setup.

Generated bindings, generated Nim source, examples, scripts, and build support
added to this repository should use the same Zlib terms unless there is a
specific, documented reason to use another permissive license.

## Third-Party Code

SoLoud is Zlib-licensed and compatible with commercial games. When the
birbparty SoLoud fork is vendored under `vendor/soloud/`, preserve its license
files and any upstream notices. Record the exact vendored fork commit in the
vendor documentation so downstream projects can audit the source.

The test framework dependency `bddy` is MIT-licensed. It is a development and
test dependency only; do not copy its source into this repository unless a later
task explicitly asks for vendoring and preserves its license.

## Homebrew Toolchains

Nintendo 3DS and PS Vita support depends on homebrew toolchains such as
devkitARM/libctru and VitaSDK. Those toolchains are external prerequisites.
Do not vendor proprietary SDKs, firmware, console vendor headers, sample code,
or binary blobs in this repository.

Hardware setup instructions may mention prerequisites such as `dspfirm.cdc`,
but this repository must not redistribute those files. Build scripts should
locate external toolchains through normal environment variables or documented
paths rather than copying toolchain contents into the tree.

## Test Fixtures

Audio fixtures must be generated by repository scripts or be CC0-compatible
under terms such as CC0-1.0.
Generated fixtures should document the tool, command, source parameters, and
expected output format needed to recreate them. Third-party fixtures must include
their source URL, CC0-compatible license, and redistribution proof before being
committed.

Do not commit proprietary game audio, sample-pack material with unclear
redistribution rights, console SDK assets, or recordings that require attribution
terms incompatible with simple commercial reuse.

Fixture-specific rules live in `tests/fixtures/README.md`.

## Generated Assets And Examples

Generated assets and example content should be Zlib-licensed, CC0-compatible, or
otherwise permissively licensed for commercial use. Examples should avoid
embedding third-party art, music, or sound effects unless their license is
documented next to the asset.
